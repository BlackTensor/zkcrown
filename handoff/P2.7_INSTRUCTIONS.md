# P2.7: Trigger-to-clean ratio sweep (Colab handoff)

`[GPU]` task. Per CLAUDE.md 0.5 I wrote the code and packaged it; you run it.

This trains **five** more behavioral-watermark models. They are identical to P2.3's `W*` (same
model, 45,000-image split, seed 1337, clean batch order, optimiser, schedule, 60 epochs and trigger
bundle) except for **how many trigger samples are mixed into training**:

| run | triggers per batch | on every k-th batch | trigger samples / epoch | trigger : clean |
|---|---|---|---|---|
| `p2.7_r0001` | 1 | 64 | 6 | 0.013% |
| `p2.7_r0005` | 1 | 16 | 22 | 0.049% |
| `p2.7_r0020` | 1 | 4 | 88 | 0.196% |
| `p2.7_r0078` | 1 | 1 | 352 | 0.782% |
| *(P2.3, reused)* | 4 | 1 | 1,408 | 3.13% |
| `p2.7_r1252` | 16 | 1 | 5,632 | 12.5% |
| *(P0.5 clean `W`, reused)* | 0 | – | 0 | 0 |

The ratios step by about 4x, so the curve spans three orders of magnitude around P2.3's value. The
sparse end is meant to reach the point where the triggers stop being learned. Going below one
trigger per batch needed one addition: `trigger_every` appends triggers only to every k-th batch.
With `trigger_every = 1` the trigger order is exactly P2.3's, which is tested.

## Expected runtime, VRAM and RAM

- **Runtime:** about **1 h 45 min to 1 h 55 min in total**. This is an **estimate, not a
  measurement.** P2.3 measured 1,182 s (19.7 min) for one run of this recipe on a T4. The four
  sparse runs add fewer trigger samples than P2.3, so they should take about the same. `r1252`
  adds 16 samples per batch of 128, about 9% more compute, so allow ~21.5 min. The rest is tests,
  smoke runs and the dataset download.
- **This is under the 2-hour split threshold, but not by much, so it is built to be split.** Each
  run is its own cell. You can stop after any run and continue in a new session: re-run sections
  1–5, **skip section 6**, then run the remaining section 7 cells. Cells for runs that are already
  complete skip themselves after checking the weights hash. A run cut off mid-way resumes from its
  last epoch.
- **VRAM:** small. P2.3 peaked at 378 MB allocated. `r1252`'s batches are 144 images instead of
  132, so expect well under 1 GB allocated.
- **System RAM:** roughly 2–3 GB, the same as P2.3.
- **Drive:** about 2.5 MB of checkpoints plus a 1.2 MB weights file per run.

## What to watch while it trains

- `eval_acc` should climb as in P2.3. If epoch 2 of any run still shows exactly `10.00%`, stop and
  report it.
- `trigger_acc` is a training diagnostic. **For the two sparsest runs it may stay low all the
  way through.** `r0001` sees each trigger only about 3.6 times in the whole run. That is a
  possible real result of the sweep, not something to fix in Colab: let the run finish.

## Known limits of what this will show

- **One training run per ratio.** P2.5 found that P2.3's accuracy drop (0.47 pp) cannot be told
  apart from zero on the test set. Neighbouring points on the curve may well differ by less than
  that noise. The figure shows 95% intervals that cover test-set sampling only, not seed-to-seed
  variation.
- WDR is measured on the training triggers, as in P2.4.
