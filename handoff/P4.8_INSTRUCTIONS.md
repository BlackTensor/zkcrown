# P4.8: Overwrite attack (Colab handoff)

`[GPU]` task. Per CLAUDE.md 0.5 I wrote the code and packaged it; you run it.

The thief knows how this project watermarks a model, but not `K`. They embed **their own**
watermark into the stolen **dual-watermarked `W*`** (P3.6) with **their own key**. The question is
whether the owner's two watermarks still extract afterwards.

Three variants (owner decision). Only the two that train go to Colab:

| Variant | What the attacker does | Where it runs |
|---|---|---|
| `overwrite_weight` | adds `alpha' * P_K'^T * S'` to the same carrier, post-hoc, at alpha' = 0.1, 0.2, 0.5, 1.0, 2.0 | **local CPU**, no training. Not part of this handoff |
| `overwrite_behavioral` | fine-tunes 20 epochs on the 5,000-image attacker holdout with their own 100 triggers mixed into every batch (4 per batch), at LR 0.001, 0.01, 0.05 | **Colab**, 3 runs |
| `overwrite_both` | the behavioral overwrite, then their own weight watermark at alpha' = 0.1 on the fine-tuned weights | **Colab**, 3 runs |

- **The attacker's key** is a public demo key, `SHA-256("zk-crown/p4.8/attacker-key/v1\0" ||
  "attacker-1")`. It has nothing to do with `K`. Their triggers, targets, projection and signature
  are derived from it with the owner's own code.
- **The attacker's triggers** are built from the attacker holdout, the only images the thief holds:
  N = 100, amplitude 16, per-trigger keyed targets (P2.2).
- **Fine-tuning** is the P4.5 recipe: SGD with Nesterov momentum 0.9, weight decay 5e-4, batch 128,
  crop and flip augmentation, a 1-epoch linear warmup, then cosine decay to zero. Final-epoch
  weights, no selection.
- Each LR has a matching P4.5 row without overwriting (20 epochs: 100 / 46 / 8 of the owner's
  triggers fired), so the effect of the overwrite itself can be read off.

**Colab only produces the attacked weights.** It runs `run_attack_suite.py apply`, which never
reads `K`. Accuracy and the owner's WDR and weight correlation are measured afterwards on your
machine with `run_attack_suite.py evaluate`.

## Expected runtime, VRAM and RAM

- **Runtime:** about **20 minutes in total**, plausibly 15 to 30. This is an **estimate, not a
  measurement.** It is scaled from P4.5 and P4.6's measured fine-tuning time on a T4, 3.1–3.4 s per
  epoch for the same model, data, batch size and per-epoch Drive checkpointing. This sweep is 120
  epochs (6 runs × 20), so about 7 min of fine-tuning. Each batch carries 4 extra trigger samples
  and each epoch scores 100 triggers once; I expect that to be small, but it has not been timed on a
  GPU. Building the attacker's projection takes a few seconds per run on the CPU. On top of that
  come the unit tests, the smoke run and the download.
- **Well under the 2-hour split threshold**, and splittable anyway: stop after either section 8 cell
  and continue in a new session by re-running sections 1–5, **skipping 6**, then 7 and the remaining
  section 8 cell. Complete runs skip themselves after a hash check. A run cut off mid-way resumes
  from its last epoch; a checkpoint from other starting weights, another attacker key or another
  alpha' is refused.
- **VRAM:** small. P2.3 peaked at 378 MB allocated for this model and batch size.
- **System RAM:** roughly 2–3 GB.
- **Drive:** a few MB of checkpoints plus a 1.2 MB weights file per run, roughly 30 MB in total.

## What to watch while it trains

- Each epoch prints `train_loss`, `train_acc` and `eval_acc`. **`eval_acc` is accuracy on the
  holdout the attacker is training on**, so it is a fit diagnostic, not test accuracy. `train_acc`
  includes the attacker's trigger samples.
- The LR 0.05 runs may dip early, as in P4.5. That is part of what is being measured. Let them
  finish.
- **Stop and report** if the loss becomes `nan`, or if `eval_acc` sits at exactly `10.00%` for many
  epochs.

## Known limits of what this will show

- One run per grid cell, one seed, one attacker key. GPU training is not bit-reproducible across
  sessions.
- The attacker has 5,000 images and uses the owner's own trigger design and settings (N = 100,
  amplitude 16, 4 per batch). Whether 20 epochs are enough for the attacker's triggers to embed is
  itself measured: the apply record reports the attacker's own fired count.
- The combined variant uses one alpha' (0.1, the owner's own strength). The alpha' sweep is the
  local weight-only variant.
- The attacker does not try to cancel the owner's watermark. Without `K` they do not know its
  direction; they only add their own.
- A model with two detectable watermarks does not say who was first. That is what the Phase 5
  commitment and timestamp are for, not this task.
