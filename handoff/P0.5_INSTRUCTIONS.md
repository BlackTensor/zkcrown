## Expected runtime, VRAM and RAM

- **Runtime:** roughly 20–35 minutes for 60 epochs on a T4. This is an **estimate, not a
  measurement** — I have no measured T4 timing for this model yet, which is part of what
  this run produces. The script also stops cleanly at `--max-minutes 90`, so it cannot
  turn into an open-ended session.
- **VRAM:** well under 1 GB. `main_model` is 307,946 parameters and the batch is 128
  CIFAR-10 images. Any T4 (16 GB) has an enormous margin; this run is not VRAM-bound.
- **System RAM:** roughly 2–3 GB, mostly the CIFAR-10 arrays and two dataloader workers.
  Comfortably inside Colab's ~12–13 GB.
- **Disk:** ~340 MB for the CIFAR-10 download into the ephemeral `/content`, plus about
  3.5 MB per checkpoint slot on Drive.

## If Colab disconnects

**Just re-run the notebook.** Every epoch is checkpointed to Drive, and the run resumes
from the last completed epoch. Optimizer momentum, LR schedule position, RNG state and
data order all carry over. A test cuts a run off after every epoch, resumes it each time,
and checks the result is bit-identical to an uninterrupted run (CPU; cuDNN on the GPU is
deterministic but not guaranteed bit-identical).

**Do not change `EPOCHS`, `SEED` or `BATCH_SIZE` between attempts.** Resuming under
different settings is refused with an error, because the checkpoint's LR schedule would
otherwise silently win. Changing `MAX_MINUTES` is fine.

Two checkpoint slots alternate (`ckpt_a.pt` / `ckpt_b.pt`) with a manifest naming the
current one, so a write interrupted mid-save can only ever cost the older checkpoint. The
loader falls back to the other slot automatically.

If section 8 prints `stopped_early: true`, the time budget ran out before 60 epochs.
Re-run section 7 until it prints `false`. **Do not report an early-stopped run as the
baseline** — the cosine LR schedule has not finished and the accuracy is not the
number later phases should be compared against.

## What the run actually does

- Trains `main_model` (307,946 params) on **45,000** of the 50,000 CIFAR-10 training
  images. SGD, lr 0.1, momentum 0.9, nesterov, weight decay 5e-4, cosine annealing over
  60 epochs, batch 128, random crop + horizontal flip.
- **The other 5,000 images are held out as the attacker's data**, reserved for the P4.5
  fine-tuning and P4.6 prune-then-fine-tune attacks. A fine-tuning attack run on the
  data the model already trained on is not a realistic threat model and would understate
  how much fine-tuning removes a watermark. The split is fixed by `SPLIT_SEED = 20260913`
  and does not depend on the run seed, so every phase sees the same holdout.
- Evaluates top-1 accuracy on the official 10,000-image test set. Every later accuracy
  figure in this project is measured on that same set.
- Also reports accuracy on the attacker holdout. That is a **sanity check, not a result**:
  if it tracks test accuracy, the split behaved as intended.
